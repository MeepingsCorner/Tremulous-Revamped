## 3. Rebuilding indexes and caches

- **gamedb index:** `tools/g search <name>` builds `.gamedb/` incrementally on first use; the guard rejects an index with fewer than 100 functions.
- **4K texture pack:** run `godot --path godot res://tests/hd_build.tscn` on the PC (Real-ESRGAN in `tools/esrgan`, about 1,900 files, 10.2 GB in `user://hd`). Only if it is lost.
- **HD sounds:** `tools/sfx_hd.py` (and `tools/sfx_audiosr.py`) make `user://sfx_hd`.
- **Acoustic cache:** `user://acoustics` regenerates itself.
- **FMOD / Steam Audio DLLs:** `powershell -File tools\get_audio_libs.ps1` copies them from the FMOD install into `third_party/fmod` and `godot/bin`.

## 5. Sync and self-test

- **Runner:** the owner starts `powershell -ExecutionPolicy Bypass -File tools\agent_runner.ps1` from the repo root and leaves the window open. The agent writes `.agent\queue\jNNN.ps1` with `device_commit_files`; the runner runs it, writes `.agent\out\jNNN.log` (UTF-16: `iconv -f UTF-16 -t UTF-8`) and `jNNN.done`, and moves the script to `.agent\ran\`. Job numbers continue from j169. Write job scripts with CRLF line endings.
- **Files to the PC:** put them in `.agent\in\<batch>\` with `device_commit_files` (at most 50 files and 30 MB each per call), then copy them into the repo inside a job. Never `git apply` patches on the PC (CRLF conversion breaks preflight); copy whole files. A regenerated file must get a new name: the bridge can resend an older copy under the same staged path.
- **Read-back:** after a copy, `device_stage_files` the file and compare (`diff <(tr -d '\r' < a) b`).
- **Baseline after a restore:** stage the PC's copies of the files you will change and diff them with the cloud copy before editing (this session's j137 did this).
- **Self-test on the PC** (pass conditions):
  - `godot --path godot res://tests/stage_shot.tscn -- --map=atcs --enhanced` → `stage: SUMMARY done atcs`, screenshots in `user://stage_atcs_*.png`;
  - `godot --path godot res://tests/shadow_shot.tscn` → `SUMMARY shadow_shot status=ok fails=0`;
  - LAN: the release exe `+set net_enabled 1 +map atcs`, then `server_list.exe lan` lists `LANTEST`, and `net_probe.exe <Wi-Fi IP>:30720 10 --base=godot\base` reaches `gamestate` and `spawned`.

## 6. Restore from the archive

On the PC (PowerShell, repo root), or after staging the parts into the cloud:

1. Verify each part: `Get-FileHash -Algorithm SHA256 handover\*.part*` against `SHA256SUMS`.
2. Join: `cmd /c copy /b "handover\tremulous-handover-2026-10-05.tar.xz.part00"+"...part01"+… joined.tar.xz` (in the cloud: `cat *.part* > joined.tar.xz`), and check it against `SHA256SUMS.full`.
3. Extract: `tar -xf joined.tar.xz -C restore`.
4. Repo: `git clone restore\repo.bundle trem` (cloud: `git clone repo.bundle /root/trem`), then `git -C trem log -1 --format=%H` must equal the head in `RESTORE.txt`.
5. gamedb (cloud): `git clone restore/gamedb.bundle /home/claude/gamedb && cd /home/claude/gamedb && cargo build --release && cp target/release/gamedb /usr/local/bin/`; then apply `tools/gamedb-patches/*.patch` if `git log` lacks c3da5da. `cp restore/ccheck.sh /usr/local/bin/ccheck`.
6. Game data in the cloud: stage `godot\base\*.pk3` from the PC when a test needs them (about 100 MB).
7. On the PC the repo already exists; restoring there is only needed if it is lost (`git clone repo.bundle` into the same path).

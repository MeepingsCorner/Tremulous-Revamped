## 1. Purpose and standing rules

The project ports Tremulous (tremulous-legacy C) to Rust (`crates/trem_sim`: game, server, client, network) rendered by Godot 4.7.2 through a GDExtension (`crates/trem_godot`). The owner, Joe, runs nothing himself except the job runner (§7).

Standing rules, from the owner and `docs/TOKEN_METHOD.md` §2 (R1–R11):

1. **Commit each finished piece of work; never push.** There is no remote. Commit messages end with the session's attribution lines.
2. **Locate code through gamedb** (`tools/g`, R1). This session mostly used `grep` in the cloud copy; the next one should go back to `tools/g`.
3. **Enhancements are options; vanilla is the default; F10 toggles;** each enhancement has a `sheets/decisions.tsv` row (R3).
4. **Stay server compatible:** nothing may break joining vanilla 1.1.0 (protocol 69) or 1.3 / legacy (protocol 71) servers; optional packs stay outside the pk3 search path (R4).
5. **Never close the owner's Godot windows.** A job that replaces `godot/bin/trem_godot.dll` waits for the file to be free (R5).
6. **Never print or echo the Discord bot token** (it lives in the Claude Desktop config). Never type passwords, keys or tokens into anything.
7. **Owner approvals:** exporting or re-exporting the standalone game, downloads, anything published, firewall or router changes (the owner does those himself), and any deletion. Instead of deleting, move files aside (`_test_leftovers/` in the user data folder is the precedent).
8. **Never overwrite the owner's personal files** (`autogen.cfg`, `admin.dat`, `qkey`, favourites). A test that sets archived cvars (`net_enabled`, `r_hdTextures`) backs up `autogen.cfg` first and restores it (jobs j153–j167 do this).
9. **Private and proprietary data stay out of git and archives:** the 4K packs (`user://hd`, `user://sfx_hd`, derived from the game data), FMOD and Steam Audio binaries (`third_party/fmod`, `godot/bin/fmod.dll`, `phonon*.dll`), `tools/esrgan`. The Tremulous 1.1.0 pk3s (CC BY-SA 2.5 media) are not in git either.
10. **Faithfulness:** every deviation or addition gets a `decisions.tsv` row (`dec001`…`dec046`). Preflight (`sheetty-cli preflight`) gates every build and rejects bad enum values (only `Easy`/`Medium`/`Hard` are valid reversibility values) and CRLF in sheets.
11. **Documents owned elsewhere:** none known. `README.md`, `docs/`, `sheets/` and `reports/` are all repo-owned.

## 10. Token lessons new this session

- PowerShell `-match` is case-insensitive: `"0 failed" -match "FAILED"` is true. Use `-cmatch` in commit gates (it blocked two commits).
- Do not reuse `$t` (or any gate variable) as a `foreach` variable in a job: it silently overwrote the test result (j139).
- `@(@(a,b,c))` flattens to strings; a one-row table needs `@(,@(a,b,c))`.
- A Godot release build reads Quake-style `+set …` from `get_cmdline_args`, not `get_cmdline_user_args` (that needs `--`).
- Godot release logs are empty when the process is killed; redirect stdout (`-RedirectStandardOutput`) to keep them.
- Window screenshots from a job: call `SetProcessDPIAware()` first and use `PrintWindow(h, dc, 2)` on the largest window of the PID; `CopyFromScreen` without DPI awareness grabs the wrong area.
- `device_commit_files` re-sent a cached older copy of a re-generated file with the same staged path; give regenerated files a new name (`decisions_v2.tsv`).
- `pkill -f godot` in the cloud kills the agent's own shell when its command line contains "godot".
- Re-running the export does not refresh `trem_godot.dll` in the release folder; copy it in each job that builds.
